## 1. 背景与目标

### 1.1 背景
合并前，宿舍数据散落在三处：初高部宿舍（`sms_class_jh`）、大学部宿舍、实训基地宿舍（`sms_job`），
另有一份只给旧教务页用的 `sms_edu` 宿舍表（66 间）。班主任、教务、校长的视图各不相同，
「分派给哪个班」「谁住哪张床」「学生档案里的宿舍号」三边经常对不上。

### 1.2 目标
1. **一个入口**：所有学段的宿舍管理合并成一个页面，按学段页签切换。
2. **一条写入口**：床位只由「宿舍管理」写入（入住 / 调宿 / 退宿 / 审批），
   学生档案等位置只读展示，杜绝两处写同一份数据。
3. **班主任自治**：班主任只看自己班的房间，能给自己班的学生办入住、退宿，发起调宿/退宿申请。
4. **数据一致**：学生的宿舍信息按学号同步到全部学生投影表，学生档案详情自动带出。

### 1.3 非目标
- 不做水电抄表、物品报修、访客登记等后勤模块。
- 不做学生自助申请（当前由班主任代申请）。
- 不删除旧路由（`/edu/dorm` 等），观察期内保留可回退。

## 2. 角色与权限

| 角色 | 页面可见范围 | 关键操作 |
|---|---|---|
| 系统管理员 | 全部房间、全部学段 | 增删改房间、分派、楼栋设置、审批、只读总闸（默认禁写） |
| 校长 / 学管主任 | 全部房间 | 分派、审批、楼栋设置 |
| 教务老师 | 全部房间 | 分派、审批、楼栋设置 |
| 班主任 | **只有「宿舍房间」页签**；房间 = 分派给本班的 ∪ 本班学生已入住的 | 办理入住、退宿、发起调宿/退宿申请 |
| 教员 / 助教 | 同班主任（按名下班级） | 同班主任 |

> 权限由页面权限码驱动：`classjh:dorm:view` / `class:dorm:view` / `job:dorm:view`（任一即可见合并页），
> 写操作另有 `requirePage` + 数据范围双重校验；前端菜单与后端接口同源下发，不存在「前端藏了但接口能调」。

## 4. 功能需求

### 4.1 宿舍房间（首页签）

**列表**
- 字段：楼栋、房号、性别（男寝/女寝/不限）、状态（使用中/空置/维修/停用）、
  床位数、已住人数、入住率、归属班级、备注。
- 筛选：楼栋、性别、状态、入住率（后端实时下发可选档位）、关键字（楼栋/房号模糊）。
- 汇总卡：当前筛选下的房间数、总床位、已住、空闲、整体入住率。
- 排序：楼栋 → 房号。

**房间维护（仅教务及以上）**
- 新增 / 编辑：楼栋（取自「楼栋设置」字典）、房号、性别、床位数、状态、备注。
- 删除：软删；房间下仍有在住学生时禁止删除。
- 床位数变化时自动补齐 / 裁剪床位行。

**床位抽屉（点「床位」）**
- 每间房一张床位矩阵：床位号（`1-上`/`1-下`/`2-上`…）、状态（空闲/已占用/停用）、
  在住学生（姓名、学号、性别、班级、入住日期）。
- 空闲床位上「入住」按钮 → 打开办理入住弹窗；已占用床位上「退宿」按钮。

**办理入住弹窗**
- 字段：房间（只读）、床位（只读）、**班级**、**学生**、入住日期（默认今天）。
- 班级下拉：房间**已分派给某班**时只出现该班并自动预选；未分派时列出数据范围内全部班级。
- 学生下拉：远程搜索（姓名/学号），候选 = 数据范围内、所选班级、**未入住**、在读、
  **性别与房间一致**（男寝只出男生、女寝只出女生）。
- 提交后：占床位 → 刷新已住人数 → 学生宿舍信息同步。

**退宿**
- 已占用床位点「退宿」→ 二次确认 → 释放床位、清空学生宿舍信息。
- 学生同时存在于多张投影表时，全部清空。

### 4.2 分派宿舍（第二页签）

**用途**：教务把房间分派给班级；分派后该班班主任立刻能在这间房里给学生办入住。

- 左侧：班级下拉（**收窄为「当前有学生的教学班」**，排除已封班的班）。
- 右侧：男寝 / 女寝两栏，各列房间（楼栋-房号、剩余床位、归属班、锁定标记）。
- 交互：
  - 勾选房间 → 「分派给 XXX 班」；已归属本班的房间可取消勾选移除分派。
  - **开放班锁定**：房间分派给一个「开放中」的班后锁定，其他班不能再分这间；
    只有该班自己的班主任能往里填学生。
  - **封班解锁**：班级封班后房间自动解锁，空床位交回教务继续调配。
  - **无学生也能分**：新班没有学生时，男女两栏合计不超过 100 个床位即可分派。
  - 分派后该班在房间列表的「归属班级」列可见。

### 4.3 申请审批（第三页签）

**用途**：班主任的换宿 / 退宿申请，由教务（或校长/学管）审批。

- 列表字段：学生（姓名/学号/班级/性别）、业务类型（调换宿舍 / 退宿）、
  原房间床位、目标房间床位、申请原因、申请人、申请日期、状态（待审批/通过/驳回）、审批人、审批意见。
- 筛选：状态、业务类型、关键字；分页。
- 操作：通过、驳回（驳回必填理由）。
- **通过的副作用**（服务端单事务）：
  1. 调宿：释放原床位 → 占用目标床位 → 更新学生宿舍信息；
  2. 退宿：释放原床位 → 清空学生宿舍信息；
  3. 目标房间与原房间的已住人数重算；
  4. 学生宿舍信息按学号同步到全部学生投影表（学生档案详情自动更新）。
- 驳回：仅改状态与理由，不动床位。

### 4.4 楼栋设置（第四页签）

- 楼栋字典字段：楼栋名称、性别（男寝/女寝/不限）、层数、每层房间数、每间床位数、排序、备注。
- 新增楼栋时可按配置**自动生成房间与床位**（层数 × 每层房间数 × 每间床位数）。
- 楼栋是「宿舍房间」「分派宿舍」楼栋下拉的唯一数据源；设置页没有的楼栋不出现在任何下拉里。
- 与「宿舍管理」实时一致：加一栋，房间/分派页的楼栋下拉立刻多一项。

## 5. 核心业务规则

| # | 规则 | 说明 |
|---|---|---|
| R1 | **性别一致** | 房间有性别（男/女）时，只能入住相应性别的学生；候选学生在弹窗里就按性别过滤，后端再兜底校验 |
| R2 | **班级分派锁定** | 开放班的房间锁定，别的班不能分、不能入住；本班班主任可以 |
| R3 | **封班解锁** | 班级封班 → 房间解锁，空床交回教务 |
| R4 | **班主任数据范围** | 分派给本班的房间 ∪ 本班学生已入住的房间。学生被调到非本班分派的宿舍、审批通过后，新房自动进入该班主任范围（无需额外授权） |
| R5 | **写入口唯一** | 床位与学生宿舍只由宿舍管理写入；学生档案的宿舍号/床位号只读展示，保存时原值回传 |
| R6 | **学号同步** | 同一学生在库内有多份投影（id 不同、学号相同），入住/退宿/审批通过后按学号同步全部投影表 |
| R7 | **空班分派上限** | 无学生的班级也可分派，男女合计 ≤ 100 床 |
| R8 | **床位号权威** | 床位号以床位表 `bed_status=2` 关联的学生为准；学生表只有档案表带 `bed_no` 列 |
| R9 | **状态口径** | 房间：使用中/空置/维修/停用；床位：空闲/已占用/停用；申请：待审批/通过/驳回 |
| R10 | **软删与唯一键** | 分派关系按房间维度唯一，复活需按单列查，避免唯一键冲突 |

## 6. 数据模型

| 表 | 作用 | 关键字段 |
|---|---|---|
| `sms_job.t_job_dorm` | 房间主表（合并后的权威房间数据） | `id, building, room_no, dorm_gender, dorm_status, bed_count, used_count` |
| `sms_job.t_job_dorm_bed` | 床位表 | `id, dorm_id, bed_no, bed_status, student_id, student_no, student_name, student_gender, check_in_date` |
| `sms_common.t_dorm_building` | 楼栋字典（楼栋设置的唯一数据源） | `id, building_name, dorm_gender, floor_count, rooms_per_floor, bed_per_room, sort_no` |
| `sms_edu.t_edu_dorm_assignment` | 班级↔房间分派关系 | `room_id, class_name, status`（开放/封班） |
| `sms_edu.t_edu_dorm_change` | 换宿/退宿申请单 | `biz_type(1调宿/2退宿), student_id, student_no, old_dorm_id, new_dorm_id, new_bed_no, status, reason` |
| 学生投影表 ×5 | 初高档案 / 大学 / 实训 / 教务 / 门户 | `student_no`（同步键）、`dorm_id`、`dorm_no`、档案表另有 `bed_no` |

> 同一学生在 5 张表里的 `id` 不同（如档案 `JHS-J26001`、门户 `PSB-J26001`），**学号是唯一可靠关联键**。

## 7. 接口清单

基址 `/api/teaching/dorm`，均需登录 token；页面权限码任一即可见，数据范围由服务端按角色计算。

| 方法 | 路径 | 用途 | 备注 |
|---|---|---|---|
| GET | `/list` | 房间列表（按数据范围过滤） | 分页 + 筛选 + 汇总 |
| GET | `/detail` | 房间详情 | 同样受数据范围约束 |
| GET | `/beds` | 某房间床位（含在住学生） | 班主任只能开自己范围内的房间 |
| GET | `/residents` | 在住学生名单（跨房间） | 按范围过滤 |
| GET | `/candidates` | 入住候选学生 | 支持 `stage/keyword/classId/className/gender` |
| GET | `/classes` | 入住弹窗的班级下拉 | 班主任只回名下班级 |
| GET | `/buildings` | 楼栋下拉 | 取楼栋字典 |
| GET | `/meta` `/summary` `/occupancy-rates` | 学段元数据 / 汇总 / 入住率档位 | |
| POST | `/save` | 新增 / 编辑房间 | 仅教务及以上 |
| POST | `/delete` | 删除房间（软删） | 有在住学生时拒绝 |
| POST | `/assign` | 办理入住 | 校验性别、班级锁定、数据范围 |
| POST | `/checkout` | 退宿 | 释放床位 + 清学生宿舍 |
| GET | `/change/list` | 申请列表 | |
| POST | `/change/create` | 发起调宿/退宿 | 班主任可发起；目标房间按班级锁定校验 |
| POST | `/change/approve` | 审批通过 | 自动改床位 + 同步学生宿舍 |
| POST | `/change/reject` | 审批驳回 | 只改状态 |

楼栋设置接口：`GET/POST/DELETE /api/teaching/building/*`（权限走宿舍域页面码，不再单独授权）。

## 8. 状态机

**房间**：使用中 →（无在住）空置 /（报修）维修 /（停用）停用；停用房不可入住。
**床位**：空闲 → 已占用（入住）→ 空闲（退宿/调宿释放）；停用床不可选。
**申请**：待审批 → 通过（执行副作用）/ 驳回（记录理由，无副作用）。

## 9. 边界与异常

| 场景 | 行为 |
|---|---|
| 男寝选到女生 / 女寝选到男生 | 下拉阶段就过滤掉；接口再校验并拒绝（「性别不匹配」） |
| 往别的开放班的房间里填学生 | 拒绝：「该宿舍已分派给开放中的 XX 班」 |
| 班主任调宿目标选到别的开放班的房间 | 前端下拉置灰该房间；后端同样拒绝 |
| 班主任凭房间 ID 直接请求别的房间床位 | 拒绝：「该宿舍不在你的数据范围内」 |
| 学生已住过别的床 | 入住时先释放旧床位（换寝兜底） |
| 房间下仍有在住学生 | 禁止删除房间 |
| 学段学生表无在读学生（演示库） | 自动回退门户学生表，三层兜底不报「学生不存在」 |
| 班级封班后 | 房间解锁，空床位重新可选 |
| 同一学生多份投影 | 按学号同步，档案详情与列表自动更新 |

## 10. 非功能需求

- **性能**：列表分页（默认 20，上限 100）；床位按房间懒加载；候选学生上限 50~100。
- **安全**：数据范围全部在服务端计算（`scopedDormIds`），前端只做展示；
  页面权限码 + 操作权限码双重校验；软删而非物理删除。
- **审计**：所有写操作留 `create_by/update_by`（脚本写入标记 `script:*`）。
- **可回退**：旧路由与旧页面全部保留，合并页可随时切回。

## 11. 统计口径

- 房间已住人数 = 该房间 `bed_status=2` 的床位条数（实时数床位表，不信房间表计数）。
- 入住率 = 已住 / 总床位，列表按楼栋-房号排序展示。
- 汇总卡 = 当前筛选条件下的房间数、总床位、已住、空闲、整体入住率。
