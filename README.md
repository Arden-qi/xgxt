# 良志学管系统（统一门户版）

良志学管系统把原先分散的招生咨询、财务、权限、就业、教务和班级业务整合到同一套 Web 系统中。项目采用一个 Vue 前端、一个 Express 后端和统一登录入口；业务数据按模块保存在同一 MySQL 实例的多个数据库中。

## 项目解决什么问题

- 将多套独立业务系统和登录入口整合，减少重复登录、分散维护及跨部门查找信息的成本。
- 支持学员从咨询、缴费、入班、在校教学、实训到就业的业务衔接，并通过学号关联跨模块的学员信息。
- 让不同部门和岗位在统一账号体系下按模块、页面、角色及操作权限访问业务，减少越权操作。
- 通过财务、班级、教务等模块间的数据同步，避免同一业务信息在不同系统中重复录入。

## 主要功能

系统包含统一门户和以下七个业务板块，实际可见页面和操作以账号权限配置为准。

- **统一门户**：统一登录、账号信息和按授权显示的模块菜单。
- **市场咨询**：学生线索与学员管理、收款缴费、审批、退费、流失记录，以及咨询学员分班/入班。
- **财务管理**：财务概览、缴费及凭证、退费、冻结名单、账单明细、费用标准；缴费信息可供相关教学业务使用。
- **权限管理**：部门、角色、用户、角色权限分配、页面可见性配置和操作日志。
- **就业管理**：实训班级、考勤、考试成绩、催费、退费、宿舍、学员流程审批，以及就业档案、就业记录、复盘和统计。
- **教务管理**：学生档案、宿舍和缴费管理。
- **班级管理（大学部）**：班级与花名册、咨询学员接收、考勤、成绩、考试、催费、退费、审批、宿舍及升实训交接。
- **教学管理（初高）**：学生与班级、考勤、考试和成绩、宿舍、催费、退费、审批及教学设置。
- **统一教学接口**：为就业实训、大学部和初高教学提供统一的教学业务入口；旧模块接口仍在项目中保留。

## 技术与目录

- 前端：Vue 3、TypeScript、Vite、Element Plus、Pinia，使用 hash 路由。
- 后端：Node.js、Express、TypeScript、Knex、MySQL。
- 共享类型：`shared-types/`，前后端共用类型定义。
- `server-job/`：后端源码、数据库迁移、上传文件和环境配置。
- `web-job/`：前端源码与 Vite 配置。
- `数据库导出/`：门户、咨询、财务和权限数据库的 SQL 导出；启动器仅在对应数据库没有表时导入。
- `数据库备份/`、`docs/`、`系统板块与页面总览.md`：历史数据备份、设计/验证资料和板块页面说明。
- `tools/`：启动、停止、环境检查及维护/验证脚本。

> 公开源码忽略规则会排除数据库导出/备份、运行时上传和本机日志。这些本地文件可能包含个人资料或业务数据，不能直接放入公开仓库或发布包。公开克隆不会附带数据库初始化数据；需要由部署方提供经过授权和脱敏的初始化数据。

## 安装方法

### 环境要求

- Windows（项目提供 `.bat` 启动脚本）
- Node.js 18 或更高版本，以及 npm
- MySQL 或兼容服务；`.env.example` 中默认连接 `localhost:3306`，数据库账号需要有权限创建数据库、建表和导入 SQL

### 推荐方式：一键启动

1. 将项目源码包解压到本机目录，保留 `shared-types/`、`server-job/`、`web-job/` 和 `tools/` 等目录。公开发布包不包含数据库导出；若有经授权并完成脱敏的初始化 SQL，请由部署方单独放入 `数据库导出/`。
2. 启动 MySQL 服务。
3. 若没有 `server-job/.env`，将 `server-job/.env.example` 复制为 `server-job/.env`；填写 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`JWT_SECRET` 和 `INTERNAL_TOKEN`。模板值是占位符，必须替换。默认数据库名为 9 个 `sms_*` 数据库，通常无需修改。请勿将含真实凭据的 `.env` 对外分享。
4. 双击项目根目录的 `一键启动.bat`。启动器会检查环境、安装缺少的 npm 依赖、编译共享类型、创建所需数据库、运行五组数据库迁移，并在门户/咨询/财务/权限库为空时尝试导入部署方提供的 SQL 数据（若未提供则跳过），最后启动前后端。
5. 首次安装也可以直接在项目根目录运行 `node tools/start.mjs`。加 `--no-browser` 可跳过自动打开浏览器；加 `--frontend=5174` 可更改前端端口（默认 5173）。

### 手动安装

先按上一节配置并启动 MySQL，然后在项目根目录依次执行：

```bat
cd shared-types
npm install
npm run build

cd ..\server-job
npm install
npm run migrate

cd ..\web-job
npm install
```

手动方式不会自动导入 `数据库导出/` 中的数据。需要这些库时，请由数据库管理员提供并导入经授权和脱敏的 SQL 初始化文件。运行迁移前确认 `.env` 指向正确的 MySQL 实例和数据库；迁移会创建或更新业务表。

## 使用方法

### 启动与访问

- 推荐运行根目录 `一键启动.bat`；也可在三个子项目分别启动：
  - `shared-types/`：`npm run build`（前后端启动前需要编译）
  - `server-job/`：`npm run dev`（后端）
  - `web-job/`：`npm run dev`（前端）
- 默认前端地址：<http://localhost:5173>
- 默认后端健康检查：<http://localhost:8004/health>
- 前端开发服务器会将 `/api/*` 请求代理到后端。端口如有修改，以启动参数、`server-job/.env` 和 `web-job/vite.config.ts` 的配置为准。
- 停止服务：双击根目录 `stop-all.bat`。它会停止项目使用的前后端端口服务，不会停止 MySQL。

### 登录和业务操作

1. 使用权限管理员维护的系统账号登录门户。账号、密码和可访问模块由部署环境中的账号与权限数据决定；不要依赖历史文档中的演示账号或密码。
2. 登录后，从侧边栏进入账号获准访问的业务板块。菜单、页面和操作按钮可能因角色权限而不同；直接输入无权访问的页面或调用无权操作时，系统会执行权限校验。
3. 在相应板块完成学员、缴费、班级、考勤、成绩、宿舍、审批及就业等日常业务。跨模块流转按页面上的业务操作执行，例如咨询分班/入班、大学部班级升实训；系统按学号关联学员，并同步到相应业务库。
4. 通过“权限管理”板块维护部门、用户、角色及页面/操作授权。权限变更范围取决于当前账号是否获准管理权限。

### 数据和演示环境

- 系统使用 9 个数据库：`sms_job`、`sms_edu`、`sms_class`、`sms_common`、`sms_class_jh`、`sms_portal`、`sms_consult`、`sms_finance`、`sms_perm`。它们应位于同一个 MySQL 实例中，项目存在跨库读取和同步。
- 一键启动仅对五个业务数据库运行迁移；门户、咨询、财务和权限的初始表/数据可由部署方放在 `数据库导出/`。公开源码包不附带这些数据；若数据库已有表，启动器会跳过 SQL 导入，避免覆盖现有数据。
- 新建空环境完成一键启动后，如需生成项目内置的完整演示业务数据，可在 `server-job/` 执行 `npm run seed:all`。**该脚本会重建多个业务库中的演示数据，执行前先确认连接的是可丢弃的演示环境并备份重要数据。**
- 生产或正式使用前，应由部署负责人配置真实账号、数据库权限及安全密钥；在 `server-job/.env` 中配置真实数据库凭据和随机 JWT/内部令牌密钥，并妥善保管数据库备份及上传文件。
